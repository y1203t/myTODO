# ToDoList 互動式待辦事項網站
## 系統需求與設計規格書

**文件版本：** V1.0

**專案名稱：** ToDoList

**專案類型：** 互動式待辦事項管理網站

**開發技術：** HTML5、CSS3、JavaScript

**開發架構：** 純前端網頁

**設計風格：** 莫蘭迪色系、柔和、簡約、可愛

**執行環境：** Google Chrome、Microsoft Edge 等現代瀏覽器

# 一、專案概述

## 1.1 專案背景與目的

隨著日常生活、課業與工作事項增加，使用者需要一個簡單且方便的工具來管理待辦事項。

本專案旨在開發一個具有基本互動功能的待辦事項網站，讓使用者能夠快速新增、查看、完成及刪除任務，並透過任務統計與進度條掌握完成情況。

網站採用低飽和度的莫蘭迪色系，以柔和、簡潔的介面降低視覺負擔，同時加入簡單的動畫與操作回饋，提升使用體驗。

## 1.2 開發目標

1. 建立簡單直覺的待辦事項管理介面。
2. 提供新增、完成、取消完成及刪除任務功能。
3. 支援不同任務狀態的篩選。
4. 即時顯示任務數量、完成比例及進度條。
5. 透過簡單動畫增加網頁互動性。
6. 使用瀏覽器本機儲存功能保存任務資料。
7. 支援電腦及手機瀏覽。
8. 僅使用 HTML、CSS、JavaScript 完成所有功能。

## 1.3 目標使用者

- **學生：** 管理作業、考試及讀書計畫。
- **一般使用者：** 記錄日常生活及工作事項。
- **時間管理需求者：** 透過任務清單掌握待辦事項。

## 1.4 專案範圍

本系統為單頁式網頁應用程式，所有功能集中在同一個頁面，不需進行頁面跳轉。

第一版本以個人任務管理為主，不提供多人協作、會員登入或雲端同步功能。

# 二、系統功能需求

## 2.1 核心功能

| 編號 | 功能名稱 | 功能說明 |
|---|---|---|
| F01 | 新增任務 | 輸入任務名稱後，點擊「新增」按鈕或按下 Enter 建立新任務。 |
| F02 | 完成任務 | 點擊任務左側核取方塊，將任務標記為已完成。 |
| F03 | 取消完成 | 再次點擊核取方塊，將任務恢復為未完成狀態。 |
| F04 | 刪除任務 | 點擊任務右側刪除按鈕，移除指定任務。 |
| F05 | 任務篩選 | 提供全部、未完成、已完成三種篩選模式。 |
| F06 | 任務統計 | 即時顯示全部任務數量及已完成任務數量。 |
| F07 | 完成進度條 | 自動計算任務完成百分比並更新進度條。 |
| F08 | 本機資料儲存 | 使用 localStorage 保存任務，重新整理網頁後仍保留資料。 |

## 2.2 功能詳細規格

### F01：新增任務

**輸入：** 任務名稱。

**操作方式：**

1. 使用者在輸入框中輸入任務內容。
2. 點擊「＋ 新增」按鈕或按下 Enter。
3. 系統檢查輸入內容。
4. 若輸入有效，建立一筆新任務。
5. 新任務顯示在待辦清單中。
6. 清空輸入框，供使用者繼續新增。

**限制條件：**

- 不允許新增空白任務。
- 只包含空格的內容視為無效。
- 任務名稱最多 100 個字元。
- 新增任務預設為未完成狀態。
- 不限制相同文字的任務重複出現。

### F02、F03：完成與取消完成任務

**操作方式：**

1. 點擊任務左側的核取方塊。
2. 系統切換任務完成狀態。
3. 若任務已完成，文字呈現刪除線及淡色。
4. 再次點擊可恢復未完成狀態。
5. 系統即時更新任務統計及完成進度。

### F04：刪除任務

**操作方式：**

1. 點擊任務右側的垃圾桶圖示。
2. 系統刪除指定任務。
3. 更新畫面中的任務清單。
4. 重新計算任務數量及完成比例。
5. 更新 localStorage。

第一版本採直接刪除方式，不加入額外的確認視窗，以保持操作簡單。

### F05：任務篩選

提供三種篩選模式：

| 模式 | 顯示內容 |
|---|---|
| 全部 | 顯示所有任務 |
| 未完成 | 僅顯示尚未完成的任務 |
| 已完成 | 僅顯示已完成的任務 |

**補充規則：**

- 網頁首次載入時預設顯示「全部」。
- 目前選取的篩選按鈕會以不同背景顏色標示。
- 切換篩選只影響顯示內容，不修改任務資料。
- 新增任務後自動切換至「全部」，確保新任務可見。

### F06、F07：任務統計與完成進度

系統需要計算以下數值：

- 任務總數
- 已完成任務數
- 完成百分比

**完成百分比計算方式：**

完成百分比 = 已完成任務數 ÷ 任務總數 × 100%

例如：

當共有 5 個任務，其中 3 個已完成：

完成百分比 = 3 ÷ 5 × 100% = 60%

**特殊情況：**

- 當任務總數為 0 時，完成百分比顯示 0%。
- 當所有任務完成時，進度顯示 100%。
- 篩選任務不影響整體完成百分比。
- 新增、刪除或切換完成狀態後，立即更新數值。

### F08：本機資料儲存

使用瀏覽器提供的 localStorage 儲存任務資料。

**儲存時機：**

- 新增任務後
- 完成任務後
- 取消完成任務後
- 刪除任務後

**資料載入：**

1. 使用者開啟網頁。
2. JavaScript 檢查 localStorage 是否存在任務資料。
3. 若有資料，載入先前的任務清單。
4. 若沒有資料，顯示空白清單。

資料只保存在目前瀏覽器中，不提供跨裝置同步。

# 三、網頁互動需求

## 3.1 互動功能

| 編號 | 功能 | 互動效果 |
|---|---|---|
| I01 | 按鈕懸停 | 滑鼠移入時，按鈕顏色或陰影產生細微變化。 |
| I02 | 按鈕點擊 | 點擊時顯示短暫的縮放回饋。 |
| I03 | 任務新增 | 任務卡片以淡入效果出現。 |
| I04 | 任務完成 | 任務文字顯示刪除線並降低顏色強度。 |
| I05 | 進度條變化 | 進度條長度以平滑動畫更新。 |
| I06 | 篩選切換 | 目前選取的按鈕顯示不同背景色。 |
| I07 | 空清單提示 | 沒有符合條件的任務時顯示提示。 |
| I08 | 完成鼓勵訊息 | 所有任務完成時顯示鼓勵文字。 |
| I09 | 輸入錯誤 | 輸入無效時顯示文字提醒。 |

## 3.2 提示訊息

| 情境 | 顯示文字 |
|---|---|
| 尚無任務 | 目前還沒有待辦事項，新增一個吧！ |
| 無未完成任務 | 沒有未完成的任務！ |
| 無已完成任務 | 目前還沒有完成的任務。 |
| 空白輸入 | 請先輸入待辦事項！ |
| 任務完成 100% | 太棒了！所有任務都完成了！ |
| 任務尚未全部完成 | 一點一點完成，繼續加油！ |

## 3.3 動畫設計原則

- 動畫時間以 0.2～0.4 秒為主。
- 避免過度跳動及大幅度位移。
- 優先使用 CSS transition 與 animation。
- 不使用額外的 JavaScript 動畫套件。
- 以柔和、自然的互動效果為主要方向。

# 四、網頁介面設計

## 4.1 整體設計風格

網站採用莫蘭迪色系，以低飽和度、帶灰調的色彩為主。

整體風格設定為：

- 柔和、簡約
- 帶有一點可愛感
- 圓角卡片
- 淡色陰影
- 清晰易讀的文字
- 適當留白
- 不使用過多裝飾

## 4.2 莫蘭迪配色規劃

| 使用區域 | 顏色名稱 | 色碼 |
|---|---|---|
| 網頁背景 | 燕麥米白 | `#F5F1ED` |
| 主要操作按鈕 | 霧玫瑰 | `#C9A7A3` |
| 篩選選取狀態 | 灰紫色 | `#B5ACC4` |
| 完成進度條 | 奶茶棕 | `#B7A494` |
| 卡片背景 | 暖白色 | `#FFFCFA` |
| 主要文字 | 深灰棕 | `#5D5552` |
| 次要文字 | 灰棕色 | `#756965` |
| 卡片邊框 | 淡灰米色 | `#E8E0DA` |

**配色使用原則：**

1. 網頁背景以燕麥米白為主。
2. 任務卡片及主要內容區域使用暖白色。
3. 新增按鈕使用霧玫瑰色。
4. 目前選取的篩選按鈕使用灰紫色。
5. 完成進度條使用奶茶棕。
6. 文字使用深灰棕，保持閱讀清晰。
7. 不大量使用高飽和度顏色。
8. 按鈕文字應使用深色，以維持足夠的對比度。

## 4.3 字體設計

網站主要採用系統預設無襯線字體，不需額外下載字型。

建議字體：

- 中文：Microsoft JhengHei、Noto Sans TC 或系統無襯線字體
- 英文：Arial 或系統無襯線字體

| 元素 | 建議大小 |
|---|---|
| 網站標題 | 30～36px |
| 區塊標題 | 18～20px |
| 任務文字 | 15～16px |
| 按鈕文字 | 14～16px |
| 提示文字 | 13～14px |

## 4.4 網頁版面配置

整個網站使用置中的單欄式版面。

**區域一：網站標題**

- 顯示 ToDoList。
- 標題置中。
- 可搭配簡單的小圖案或裝飾。
- 不使用過於複雜的背景圖片。

**區域二：新增任務區**

包含：

- 任務輸入框
- 新增任務按鈕
- 錯誤提示文字

**區域三：任務進度區**

包含：

- 「任務進度」標題
- 已完成數量 / 總任務數量
- 完成百分比
- 橫向進度條

**區域四：篩選功能區**

包含三個水平排列的按鈕：

- 全部
- 未完成
- 已完成

**區域五：任務清單區**

每個任務顯示於獨立卡片中。

卡片包含：

- 核取方塊
- 任務文字
- 刪除按鈕

當任務名稱過長時，文字自動換行，避免超出卡片。

## 4.5 響應式設計

**桌面版：**

- 網頁內容最大寬度約 600px。
- 主內容水平置中。
- 任務卡片以垂直方式排列。

**手機版：**

- 內容寬度隨螢幕縮小。
- 保持適當的左右間距。
- 按鈕與輸入框不超出畫面。
- 任務文字可自動換行。
- 主要按鈕維持方便點擊的尺寸。

# 五、使用者操作流程

## 5.1 網頁初始化

1. 使用者開啟 ToDoList。
2. 系統讀取 localStorage 中的任務資料。
3. 初始化任務清單。
4. 預設選取「全部」篩選模式。
5. 顯示任務總數、完成數量與進度。
6. 等待使用者操作。

## 5.2 新增任務流程

1. 使用者輸入任務內容。
2. 點擊新增按鈕或按下 Enter。
3. 系統檢查內容是否有效。
4. 若無效，顯示錯誤提示。
5. 若有效，建立新任務。
6. 將任務加入清單。
7. 更新畫面、統計及儲存資料。
8. 清空輸入欄位。

## 5.3 完成任務流程

1. 使用者點擊任務核取方塊。
2. 系統切換任務完成狀態。
3. 更新任務文字樣式。
4. 更新完成數量。
5. 更新完成百分比與進度條。
6. 儲存變更。

## 5.4 刪除任務流程

1. 使用者點擊刪除按鈕。
2. 系統依任務 ID 刪除指定任務。
3. 重新顯示任務清單。
4. 更新統計資訊。
5. 儲存變更。

## 5.5 篩選任務流程

1. 使用者點擊篩選按鈕。
2. 系統記錄目前的篩選條件。
3. 根據完成狀態篩選任務。
4. 更新畫面清單。
5. 若無符合條件的任務，顯示提示訊息。

# 七、資料結構設計

## 7.1 任務資料格式

每一筆待辦事項使用 JavaScript 物件表示：

```javascript
{
  id: 1,
  text: "完成網頁設計作業",
  completed: false
}
```

| 欄位 | 型態 | 用途 |
|---|---|---|
| id | Number | 任務唯一識別碼 |
| text | String | 任務名稱 |
| completed | Boolean | 是否完成 |

## 7.2 任務清單格式

所有任務以陣列儲存：

```javascript
const tasks = [
  {
    id: 1,
    text: "完成作業",
    completed: false
  },
  {
    id: 2,
    text: "閱讀 30 分鐘",
    completed: true
  }
];
```

## 7.3 任務 ID 規則

- 每筆任務具有唯一 ID。
- 新增任務時產生新的 ID。
- 刪除任務後，不重新編排現有任務 ID。
- ID 不應因重新整理頁面而與現有任務重複。

第一版本可使用目前最大 ID 加一的方式產生新 ID。

## 7.4 localStorage 儲存規格

**儲存鍵值名稱：**

`todoListTasks`

**儲存內容：**

任務陣列轉換後的 JSON 字串。

**儲存方式：**

```javascript
localStorage.setItem(
  "todoListTasks",
  JSON.stringify(tasks)
);
```

**載入方式：**

```javascript
const savedTasks = JSON.parse(
  localStorage.getItem("todoListTasks") || "[]"
);
```

實際開發時，需加入資料格式檢查與錯誤處理，避免損壞的儲存資料造成程式無法正常執行。

# 八、非功能性需求

## 8.1 易用性

1. 使用者不需要登入即可使用。
2. 所有主要功能集中於同一個頁面。
3. 操作方式應清楚且容易理解。
4. 任務狀態改變後立即更新畫面。
5. 錯誤輸入應提供明確提示。

## 8.2 視覺一致性

1. 全站使用統一的莫蘭迪色系。
2. 按鈕、輸入框及卡片保持一致的圓角風格。
3. 使用固定的文字大小層級。
4. 不使用過多動畫或鮮豔顏色。
5. 確保主要文字與背景具有足夠對比。

## 8.3 效能需求

1. 一般任務操作應即時完成。
2. 避免使用大型外部函式庫。
3. 優先使用原生 JavaScript。
4. 不依賴網路 API。
5. 一般使用情況下，數十至數百筆任務仍應可正常操作。

## 8.4 相容性

1. 支援現代桌面瀏覽器。
2. 支援常見手機螢幕尺寸。
3. 不需安裝 Node.js。
4. 可直接開啟 index.html 使用。
5. localStorage 的可用性與保存行為依瀏覽器環境而定；正式使用時建議透過一般網站來源開啟，以確保儲存行為穩定。

## 8.5 資料安全

1. 使用者任務內容必須以純文字方式顯示。
2. 不應將輸入內容直接作為 HTML 執行。
3. 不上傳使用者資料至外部伺服器。
4. 使用者清除瀏覽器網站資料後，儲存任務可能消失。

# 十一、預期成果

本專案預計完成一個以莫蘭迪色系為視覺風格的 ToDoList 互動式待辦事項網站。

網站提供新增、完成、取消完成、刪除與篩選任務等基本功能，並能即時更新任務統計及完成進度。

透過簡單的按鈕動畫、任務狀態變化與進度條效果，使網站具有適當的互動性。

系統使用 localStorage 保存資料，讓使用者重新整理或再次開啟網站時，仍可查看先前建立的任務。

整個專案僅使用 HTML、CSS、JavaScript 實作，不需 Node.js、後端伺服器或資料庫。
